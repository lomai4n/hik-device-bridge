# 第一版推进计划

## 产品目标

用户自行安装 SDK，通过密码文件配置一台设备，运行工具登录布防，接收事件元数据，最后安全撤防、注销和退出。

不使用真实设备的开发者可以构建项目、执行模拟测试，明确区分模拟与真实运行。

## 实施顺序

1. 核实厂商公开接口资料和使用条款，记录实际查阅的公开链接；明确 Linux x86_64 的验证范围。
2. 完成最小 C++20/CMake 工程、元数据类型、回调队列及独立的合成测试。
3. 在公开资料充分时实现动态 SDK 接入和命令行工具，保留版本、错误及长度检查；缺少资料时明确限制，不猜测厂商 ABI。
4. 补齐无设备测试、构建说明、密码文件说明和中性示例，验证默认输出不包含敏感信息。
5. 检查源码、Git 内容、文档、构建日志和打包内容，公开仅模拟验收的预发布。真实 SDK 与实机连接在取得合适材料和测试环境后另行验收。

## 验收条件

- 不依赖任何其他私有项目的文件、服务或路径。
- 无真实 SDK 或设备时能构建通用层并通过合成测试。
- 缺少 SDK、必要符号或版本不匹配时，真实运行明确失败。
- 原生回调不进行输出、网络或文件操作，队列容量有界且溢出可见。
- 登录/布防失败、未知或畸形事件、退出过程中回调均有明确处理。
- 默认输出只包含设备别名、报警码、接收时间、长度及丢失计数等允许的元数据；时间不冒充设备事件时间。
- 密码、账号、事件原文、图片等敏感内容不进入日志或默认输出。
- 打包与 Git 内容不包含 SDK、现场数据、旧项目历史、内部域名、个人身份或私有业务实现。
- 支持列表只列出实际验证的 SDK/设备/事件；未做实机验证时明确标注。

## 本轮进度（2026-10-10）

已实现 C++20/CMake 通用库、模拟命令行、固定元数据有界队列、故障与丢失计数、生命周期版本比较和失败回滚、受控密码文件读取、动态库符号探测及合成测试。来源、使用约定和验收范围已记录。

真实动态 SDK 函数调用、原生版本读取与允许列表、登录/布防及原生回调尚未实现：缺少配套官方头文件和精确 ABI/版本证据。未通过真实 SDK 或设备验收。真实命令始终非零失败，不接受凭据或设备地址，不假装接入成功。首版目标中的真实路径仍未完成。

源码预发布包只含允许清单中的从零实现文件和 Apache-2.0 许可文本；不含 SDK、凭据、构建工具环境或 Git 历史。用户已授权公开模拟预发布。Linux x86_64 与实机验收仍是完整真实接入版本的发布前待办。
