# hik-device-bridge

面向 Linux 的非官方海康设备接入工具，目标是提供 C++ 库及命令行入口，完成设备连接、报警订阅和事件元数据接收。

当前状态：`v0.1.0-preview.1` 模拟预发布，通用层与模拟接入已实现。真实 SDK 接入被禁用；尚未核验具体 SDK ABI、版本或实机。项目名称暂定，未确认名称可用性。项目与海康官方无隶属关系。

第一版范围及验收标准见 [推进计划](docs/ROADMAP.md)。

SDK 由用户自行合法取得，不随本项目分发。默认不输出报警原文或图片。示例及测试只使用合成数据。

本项目原创源码和文档采用 [Apache-2.0](LICENSE)。这不授权使用或再分发厂商 SDK、头文件及配套材料；[厂商许可核对记录](docs/SDK-LICENSE.md)分别记录已读公开条款和仍待核验的具体 SDK 包条款。本预发布不附带 SDK，也不宣称厂商 SDK 的使用或集成许可已获确认。

## 构建与合成演示

需要 C++20 编译器、CMake 3.20 以上、POSIX 系统；执行测试需要 Python 3（仅标准库）。目标平台是 Linux x86_64；本轮只在 macOS ARM64 验证了通用层，不能据此宣称 Linux 或厂商 SDK 已获支持。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j 4
ctest --test-dir build --output-on-failure
./build/hik-device-bridge simulate --seconds 1 --alias camera-demo
```

本轮本地工具环境中的 CMake 位于 `.runtime/tools/bin/`，可用该目录下的 `cmake` 和 `ctest` 执行以上步骤；工具环境不会进入候选包。其他环境需自行安装 CMake。

演示完全离线，每条 JSON 都带有 `mode: simulation`。模拟版本 `1` 是本项目合成后端的版本号，不是海康 SDK 版本。命令接受 SIGINT/SIGTERM，先停止并等待生产线程，再排空队列。正常完成和信号退出返回 0；参数、输出、连接状态或清理失败返回非零。

标准输出只包含设备别名、事件类别、数值码、接收时间、载荷长度与丢失/畸形计数。标准错误明确标识模拟模式并输出最终计数。`received_unix_ms` 是本机接收时间，可能随系统时钟调整，不是设备事件时间。别名限 1–48 个 ASCII 字母、数字、连字符或下划线，请使用中性名称。

队列默认 64 个元素，可在库中配置为 1–4096。回调不读取载荷，也不保存载荷指针，仅复制固定大小的元数据；长度只用于元数据边界检查，不能证明原始内容有效。未知报警码保持数值，不猜测结构。空载荷、零长度或超过 1 MiB 的报警输入被拒绝。

队列满或锁竞争时丢弃新元数据并计入 `dropped`；畸形输入计入 `invalid`；队列关闭后的输入计入 `rejected`（此时锁竞争仍计入 `dropped`）。工作线程的接收器异常计入 `output_errors`，不输出异常原文。运行中的计数是近似快照；生产线程结束并排空后的计数才是最终值。无持久化，不承诺无丢失。CLI 将标准输出临时设为非阻塞；管道满或断开时停止并报告失败，消费者应丢弃不完整的最后一行。

## 密码文件

密码读取器及检查命令已实现，但当前模拟模式不使用凭据，真实登录还未开放。未来登录也只能通过独立文件读取密码，不能通过命令行密码值或环境变量传入。

将文件放在 `secrets/` 或项目目录之外，使用权限 0600 和受控的父目录，再执行：

```sh
./build/hik-device-bridge check-password secrets/device.password
```

文件必须是当前有效用户拥有、仅一个硬链接的普通文件；拒绝末级符号链接、FIFO 和组/其他用户可访问的文件。内容总长度限 1–127 字节，可带一个末尾 LF 或 CRLF；密码不能为空，不能含控制字节。父目录由使用者负责保护。读取器析构或构造失败时覆写自身缓冲区，不承诺清除操作系统、厂商库或使用者自行复制的内容。检查命令只返回是否有效，不输出文件内容或路径。

## 真实模式的边界

```sh
./build/hik-device-bridge real --sdk /absolute/path/to/libhcnetsdk.so
```

当前此命令始终失败：库不存在或必要符号缺失时报告明确错误；符号齐全时仍因 ABI/版本未核验而拒绝。只检查符号名称，不调用 SDK 函数，不读取版本、不登录、不布防，也不会自动降级成模拟。动态加载会执行共享库自身的初始化/析构代码，因此只对自行合法取得且可信的本地库使用此命令；它不是安全沙箱。

厂商头文件、二进制、配套依赖与资料均由使用者自行取得，不提交或打包。公开来源和后续真实接入所缺的证据见 [来源记录](docs/SOURCES.md)；本轮测试范围见 [验证记录](docs/VALIDATION.md)。

## 库使用与退出约定

`hik_bridge` 提供 `Events`、`Metadata`、`Counters`、`Password` 与通用 `Backend`/`Session` 生命周期。后者是本项目的 C++ 接口，完全不代表厂商 ABI。`Session` 在初始化前精确比较后端版本，成功后依次登录和布防；失败时撤销已取得的资源。即使撤防失败也继续注销和清理。应显式调用 `stop()` 并检查返回值，析构仅作兜底。

`Backend` 的初始化、登录、布防失败或抛异常时必须保证本步骤不残留资源；`cleanup()` 必须等待所有回调结束，即使报告失败也不能遗留回调。接收器在工作线程运行，必须能够返回，不能在接收器内调用 `stop()` 或销毁队列。生命周期调用由一个拥有线程执行；后端、队列须比 `Session` 活得更久。并发回调可以和关闭重叠，但销毁队列前必须终止并等待全部生产线程。所有异常通知都会设置故障标志，即使通知因队列满而丢失；原生异常类型和重连语义尚未实现。
